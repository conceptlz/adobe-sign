    PHP 8.2+ · Acrobat Sign REST API v6

    Contracts, signed from PHP.

    conceptlz/adobe-sign uploads your documents, sends them for signature in any order, lets each project choose the legal signature level it needs (SES, AES or QES), reports progress through webhooks and hands you the signed PDF. It runs in any PHP project and uses only PSR interfaces.

    composer require conceptlz/adobe-sign

    What it does

    Adobe Acrobat Sign is Adobe's e-signature service. Its REST API is large (agreements, documents, participants, events, webhooks, users, web forms, bulk sends) and has some details that are easy to get wrong in production: the account lives in a specific data centre, writes need the latest ETag, rate limits come with a Retry-After, and some responses differ from the published spec. This SDK handles those details, so the code you write reads like the business process:

    Features

    • Both auth methodsIntegration Key for your own account, or OAuth 2.0 so users connect their own Acrobat Sign accounts. Tokens refresh automatically, and asUser() acts on behalf of another user in the account.
    • Signing orderSequential, parallel or mixed ("client first, then CFO and legal together, then CEO") with a single order() call per participant.
    • Signature levelsSES by default, and AES or QES per project or per signer. After signing, signatureEvidence() shows what each signer actually reached.
    • Identity checksEmail one-time code, SMS, WhatsApp, password, knowledge-based questions, government ID or national eID, set with one verifyWith() call.
    • WebhooksHandles Adobe's verification handshake and turns each notification into a typed event object.
    • Production plumbingData-centre discovery with caching, retries that honour Retry-After, automatic If-Match, generators for paginated lists, streams for uploads and downloads.
    • Typed errorsOne exception per failure kind (authentication, not found, validation, rate limit, stale ETag, account capability, transport), with credentials always redacted.
    • Spec-checked313 models generated from Adobe's OpenAPI spec. Every request and response in the test suite is validated against it, and the SDK has been tested against a real account.

    Three packages, one release

    PackageUse it whenDepends on
    conceptlz/adobe-signAny PHP project: Slim, WordPress plugins, CLI tools, queues, or a framework without an integration.PSR-18/17/7, PSR-16, PSR-3, PSR-20, php-http/discovery
    conceptlz/adobe-sign-laravelLaravel 12 or 13: adds config, a facade, OAuth routes, a token table and a webhook route.this package + illuminate/*
    conceptlz/adobe-sign-symfonySymfony 7.4 or 8: adds a config tree, autowired services, OAuth routes, encrypted token storage (cache or Doctrine), a webhook route and Messenger support.this package + symfony/*

    All three packages share one version number and are always released together.

    Independent project

    This SDK is developed independently and is not affiliated with or endorsed by Adobe. You need your own Acrobat Sign account; a free developer account is enough to build and test.
